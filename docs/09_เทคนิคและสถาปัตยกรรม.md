# 09 · เทคนิคและสถาปัตยกรรม (Technical Design)

## 1. เลือก Engine

| ตัวเลือก | ข้อดี | ข้อเสีย | สรุป |
|---------|------|--------|-----|
| **Unity 6 (URP)** | เอกสาร/บทเรียนเยอะสุด, มี Toon Shader และ Asset Store มาก, Build ได้ PC/Android/WebGL, Genshin เองก็ใช้ Unity | ต้องเรียน C#, มีเงื่อนไขไลเซนส์ (ฟรีถ้ารายได้ < เกณฑ์) | ✅ **แนะนำ** |
| Godot 4 | ฟรี 100% โอเพนซอร์ส เบา เครื่องโรงเรียนรันได้ | Open world 3D ขนาดใหญ่ยังทำยากกว่า, Asset น้อยกว่า | ทางเลือกถ้าทีมเล็ก/เน้นเบา |
| Unreal Engine 5 | กราฟิกสวยสุด | หนัก, Toon style ทำยากกว่า, เครื่องโรงเรียนรันไม่ไหว | ❌ ไม่แนะนำ |

**ข้อเสนอ**: Unity 6 + URP + Toon Shader (เช่น UnityChan Toon Shader / lilToon / Toony Colors Pro)

> **อัปเดต 2026-10-06 — สิ่งที่ทำจริงในเฟส Vertical Slice:** เครื่องที่พัฒนายังไม่มี Unity/Godot จึงเริ่มเป็น **เวอร์ชันเว็บ (Three.js + TypeScript + Vite)** อยู่ในโฟลเดอร์ [`game/`](../game/README.md)
> ข้อดี: เปิดในเบราว์เซอร์บนคอมโรงเรียนได้ทันทีโดยไม่ต้องติดตั้ง, ทดสอบอัตโนมัติได้, ไฟล์เนื้อหา (JSON ใน `game/public/data/`) ใช้รูปแบบเดียวกับเอกสารนี้ จึงย้ายไป Unity ภายหลังได้
> สถาปัตยกรรมโมดูล (EventBus, Data-driven, QuestManager, QuizEngine ฯลฯ) ตรงกับหัวข้อ 3 ด้านล่าง ต่างกันแค่ภาษา (TypeScript แทน C#)

## 2. Pipeline ศิลปะ (ภาพจาก GPT → เกม)

> ⚠️ สำคัญ: ภาพจาก GPT เป็น **2D** — ใช้โดยตรงได้สำหรับ UI, ไอคอน, พอร์ตเทรต, Splash Art, Loading Screen, Concept Art
> ส่วนโมเดล **3D** ต้องใช้กระบวนการแยก

| ประเภท Asset | ที่มา | เครื่องมือ |
|-------------|------|----------|
| Concept Art / Key Art | GPT | — |
| ไอคอน (ธาตุ, ไอเทม, สกิล) | GPT → แต่งใน Photoshop/Krita (ลบพื้นหลัง, ปรับขนาด) | Krita / Photopea (ฟรี) |
| พอร์ตเทรตบทสนทนา (สีหน้า 8 แบบ) | GPT | — |
| Splash Art / Gacha Art | GPT | — |
| **โมเดลตัวละคร 3D** | ใช้ Character Sheet จาก GPT เป็นต้นแบบ → ปั้นใน **VRoid Studio** (ฟรี, เหมาะกับอนิเมะ) แล้วแต่งต่อใน Blender | VRoid Studio + Blender + UniVRM |
| โมเดลศัตรู / สิ่งของ 3D | Blender หรือเครื่องมือ AI Image-to-3D (เช่น Meshy, Tripo) แล้วรีโทโพโลยีใน Blender | Blender |
| แอนิเมชัน | Mixamo (ฟรี) สำหรับท่าพื้นฐาน + ทำเองใน Blender | Mixamo |
| ฉาก/ภูมิประเทศ | Unity Terrain + Asset Pack สไตลไลซ์ | Unity |
| VFX ธาตุ | Unity VFX Graph / Particle System | Unity |
| เสียง | Freesound / สร้างเอง / ดนตรีจ้างหรือใช้ไลบรารีที่มีสิทธิ์ | Audacity |

**ทางเลือกลดขอบเขต (ถ้าทีมเล็กมาก)**: ทำเป็น 3D แบบ Isometric/Top-down ฉากเล็ก (Hub + โซนแยก) แทน Open World ไร้รอยต่อ ใช้ระบบเดิมทั้งหมดได้

## 3. สถาปัตยกรรมโค้ด (Unity)

### 3.1 โมดูลหลัก
```
Core
 ├── GameManager            สถานะเกม, โหลดฉาก
 ├── EventBus               ระบบ Event กลาง (Publish/Subscribe) — ทุกระบบคุยกันผ่านตัวนี้
 ├── SaveManager            บันทึก/โหลด JSON (+ เข้ารหัสเบา ๆ)
 ├── DataRegistry           โหลด Data ทั้งหมด (JSON/ScriptableObject) เข้าหน่วยความจำ
 ├── LocalizationManager    ไทย/อังกฤษ
 └── AudioManager

Gameplay
 ├── Player/                การเคลื่อนที่, Stamina, กล้อง, Glider, ปีน, ว่ายน้ำ
 ├── Party/                 จัดทีม, สลับตัว, Resonance
 ├── Combat/
 │    ├── DamageCalculator  สูตรดาเมจ (ไฟล์ 02)
 │    ├── ElementSystem     Aura, Gauge, Decay, ICD
 │    ├── ReactionResolver  ตารางปฏิกิริยา
 │    ├── SkillSystem       สกิลแบบ Data-driven (ScriptableObject + Behaviour)
 │    └── EnergySystem      ATP Particles
 ├── Enemy/                 AI (Behaviour Tree / State Machine), Spawner, Mechanics (BinaryFission ฯลฯ)
 ├── Interaction/           NPC, หีบ, วัตถุโต้ตอบ
 └── World/                 Waypoint, รูปปั้น, กลางวัน-กลางคืน, สภาพอากาศ

Progression
 ├── CharacterProgression   Level, Ascension, Talent, GeneSequence
 ├── WeaponSystem
 ├── RelicSystem
 ├── InventorySystem
 ├── EconomySystem          สกุลเงิน, ATP Resin
 ├── GachaSystem            สุ่ม + Pity (RNG แบบ Seed บันทึกได้)
 ├── CraftingSystem / CookingSystem
 └── AchievementSystem

Narrative
 ├── QuestManager           (ไฟล์ 05)
 ├── DialogueSystem         อ่าน Dialogue JSON, แสดงพอร์ตเทรต, ตัวเลือก
 └── CutsceneSystem         Unity Timeline

Learning
 ├── QuizEngine             แสดงคำถาม 8 ประเภท, ตรวจคำตอบ
 ├── MasteryTracker         (ไฟล์ 07 หัวข้อ 4)
 ├── SpacedRepetition       Leitner Box
 ├── CodexSystem            Bio-Pedia, Scanner
 └── AnalyticsLogger        บันทึก Event → ส่ง Dashboard (ถ้าออนไลน์)

UI
 ├── UIManager              สแตกหน้าจอ
 └── Screens/               แต่ละหน้าจอ (ไฟล์ 08)
```

### 3.2 หลักการเขียนโค้ด
- **Data-driven**: ตัวละคร, สกิล, อาวุธ, ศัตรู, เควส, คำถาม → เป็นไฟล์ Data ทั้งหมด
- **Event-driven**: ระบบไม่เรียกกันตรง ๆ เช่น `Combat` ส่ง `EnemyDefeated` → `QuestManager`, `AchievementSystem`, `CodexSystem` รับเอง
- **ScriptableObject** สำหรับ Data ที่ต้องอ้างอิง Asset (Prefab, Sprite) / **JSON** สำหรับข้อความและข้อมูลที่ครูแก้ได้ (คำถาม, เควส)
